# Test techniques

The test techniques that run in this repository today: what each one checks here, which part of the product it covers, where it lives, how to run it and which CI job runs it. Use it to see what is covered by which kind of test and where a new case belongs. Techniques that are missing are only named at the end. How to run the checks for a change: [verification.md](verification.md). How to choose the cases: the `/testing` skill (`.claude/skills/testing/SKILL.md`).

## Key

| Layer | Part |
|---|---|
| UI | frontend UI components and screens |
| Logic | frontend state and logic (stores, pure functions) |
| Mock | the in-memory mock backend |
| Wire | the contract between frontend and backend |
| Core | backend core (novira-core) |
| Server | backend server (novira-server) |
| Shell | the Tauri shell |
| Build | build and release |
| App | the whole app, including the real engine |
| Repo | repository tooling, docs and rules |

CI is a job of `.github/workflows/test.yml` (`static`, `rust-format`, `vitest`, `clippy`, `cargo-test`, `e2e-chromium`, `e2e-phone`, `diff-backends`), of `.github/workflows/audit.yml` (`audit`) or of `.github/workflows/release.yml` (`build`). "manual" means no workflow runs it.

## Techniques

| Technique | What it checks here | Layer | Where | Run | CI |
|---|---|---|---|---|---|
| Unit | Pure logic and single modules, with the normal case, a failure and the limits | Logic, Core, Mock, Shell | `frontend/src/` (`*.test.ts`), `backend/crates/novira-core/tests/` (`*_edge_cases.rs`, `mutation_media.rs`) | `npx vitest run <path>`, `cargo test -p novira-core --lib` | `vitest`, `cargo-test` |
| Component | Screens and controls rendered in a test DOM; the open screen's copy is found among the hidden ones | UI | `frontend/src/app/phone/PhoneView.test.tsx` and the other `*.test.tsx` beside the components | `npx vitest run <path>` | `vitest` |
| Service integration | The real service on a real SQLite file and temp folders, with a fake ComfyUI and a fake website instead of the network | Core | `backend/crates/novira-core/tests/backend_service/`, `backend/crates/novira-core/tests/comfy_fake_server/`, `backend/crates/novira-core/tests/fake_site/` | `cargo test -p novira-core --test <name>` | `cargo-test` |
| Server integration | The HTTP routes, pairing, sockets and uploads of the browser server on loopback | Server | `backend/crates/novira-server/tests/auth.rs`, `backend/crates/novira-server/tests/commands.rs` | `cargo test -p novira-server` | `cargo-test` |
| Contract | Both sides read and write the same JSON samples of every wire type and keep the IPC command list equal to the capability file | Wire, Shell | `contract/`, `frontend/src/backend/contract.test.ts`, `frontend/src/backend/tauri/commands.contract.test.ts`, `backend/crates/novira-core/tests/contract/` | `npx vitest run src/backend/contract.test.ts src/backend/tauri`, `cargo test -p novira-core --test contract` | `vitest`, `cargo-test` |
| Snapshots | The ComfyUI prompts the app builds, per model family, against stored JSON; an orphan file with no writing test fails | Logic, Core | `backend/crates/novira-core/src/comfy/graph_snapshots.rs`, `backend/crates/novira-core/src/comfy/__snapshots__/`, `frontend/tests/test-hygiene.test.ts` | `npx vitest run <file>.snapshot.test.ts`, `cargo test -p novira-core --lib comfy::graph_snapshots` | `vitest`, `cargo-test` |
| Node-definition contract | Every backend snapshot prompt against the node definitions of a real ComfyUI: unknown node, input, link or choice | Core | `backend/crates/novira-core/src/comfy/node_defs_check.rs`, `backend/crates/novira-core/src/comfy/__snapshots__/node-defs.json` | `cargo test -p novira-core --lib comfy::node_defs_check` | `cargo-test` |
| Property-based (Rust) | Random input to pure functions and parsers: paths that escape, prompts with cycles, round trips, store against a model; fixed seed | Core | `backend/crates/novira-core/tests/prop_paths.rs`, `backend/crates/novira-core/tests/prop_graph.rs`, `backend/crates/novira-core/tests/prop_roundtrip.rs` | `cargo test -p novira-core --test prop_paths`; `PROPTEST_CASES`, `PROPTEST_SEED` | `cargo-test` |
| Property-based (frontend) | Random input to stores and pure logic, in process with `fetch` stubbed to throw; a known bug stays as a marked failing test | Logic, UI | `frontend/src/propertyTest.testkit.ts` and the `*.property.test.ts` files | `npx vitest run <file>.property.test.ts`; `NOVIRA_PBT_RUNS`, `NOVIRA_PBT_SEED` | `vitest` |
| Model-based | Random sequences of queue operations against a naive model, with the worker paused (so races with a running job are not covered), and the store against a model | Core | `backend/crates/novira-core/tests/prop_queue.rs`, `backend/crates/novira-core/tests/prop_db.rs` | `cargo test -p novira-core --test prop_queue` | `cargo-test` |
| State transition | Each status and event of the queue, model installs and packs; the table is a document and no check proves every cell has a case (partly) | Core, Logic | `.claude/skills/testing/reference/state-machines.md`, `backend/crates/novira-core/tests/prop_queue.rs` | `cargo test -p novira-core --test prop_queue` | `cargo-test` |
| Byte fuzzing | Valid pictures, credentials, model headers and a backup zip, each damaged and read again: no panic, no slow reader, nothing unpacked outside staging; no coverage guidance | Core | `backend/crates/novira-core/tests/fuzz_inputs.rs` | `cargo test -p novira-core --test fuzz_inputs`; `NOVIRA_FUZZ_ITERATIONS`, `NOVIRA_FUZZ_SEED` | `cargo-test` |
| Command fuzzing | The arguments of every local command damaged as JSON trees and sent through the dispatcher with the worker running; partly structure-aware | Core | `backend/crates/novira-core/tests/backend_service/api_fuzz.rs` | `cargo test -p novira-core --test backend_service`; same variables | `cargo-test` |
| Request fuzzing | Raw damaged HTTP requests to the server's routes: always answered, never a 5xx, request checks enforced, no leaked token | Server | `backend/crates/novira-server/tests/http_fuzz.rs` | `cargo test -p novira-server --test http_fuzz` | `cargo-test` |
| Differential (mock against backend) | The same calls and seeded call sequences to the mock and to the real backend through the server; every difference is a failure | Mock, Server, Core | `frontend/difftest/backends.difftest.ts`, `frontend/difftest/sequences.difftest.ts`, `scripts/tools/diff-backends.mjs` | `node scripts/tools/diff-backends.mjs`; `NOVIRA_DIFF_SEED` | `diff-backends` |
| Crash-stage tests | A restore and a data-folder move are stopped after every step k, restarted and checked whole; failures injected in restore stages, renames, downloads. Not engine or model installs (partly) | Core | `backend/crates/novira-core/src/backup/restore/crash_tests.rs`, `backend/crates/novira-core/src/data_location/crash_tests.rs`, `backend/crates/novira-core/tests/restore_stage_failures.rs` | `cargo test -p novira-core --lib crash_tests` | `cargo-test` |
| Old-data upgrade | A data folder written by an older release is opened by the current code and every board, picture, setting and job is still there | Core, Build | `backend/crates/novira-core/tests/fixtures/data-v0.3.0/`, `backend/crates/novira-core/tests/backend_service/old_data.rs` | `cargo test -p novira-core --test backend_service old_data` | `cargo-test` |
| End-to-end | User flows of the screens on the mock in Chromium, with the page's console errors failing the case | UI, Mock | `frontend/e2e/`, `frontend/playwright.config.ts` | `npm run e2e` or `npx playwright test --project=chromium` | `e2e-chromium` |
| Monkey | Seeded random clicks, typing, keys and drags on every main screen; no error boundary and no logged error after any action | UI, Mock | `frontend/e2e/monkey.spec.ts` | `npx playwright test e2e/monkey.spec.ts --project=chromium`; `NOVIRA_MONKEY_SEED`, `NOVIRA_MONKEY_ACTIONS` | `e2e-chromium` |
| Cross-browser and phone | The phone layout in Chromium as a Pixel 7 and in WebKit as an iPhone 14 (not iOS Safari, no Firefox) | UI | `frontend/e2e/phone.spec.ts`, `frontend/playwright.config.ts` | `npx playwright test --project=phone --project=webkit` | `e2e-phone` |
| Visual regression | Screenshots of the main screens against baselines, one set per platform; pre-commit demands updated baselines | UI | `frontend/e2e/visual.spec.ts`, `frontend/e2e/__screenshots__/`, `scripts/tools/visual-baselines.mjs` | `npm run e2e:visual` | manual |
| Layout scan and text fit | Every screen, dialog and menu in ja and en, dark and light, for overflow, clipped or shortened text, touching or overlapping controls; pre-commit needs a recorded pass | UI | `frontend/e2e/layout.spec.ts`, `frontend/e2e/layoutScan.ts`, `frontend/e2e/textFit.ts`, `scripts/tools/layout-scan.mjs` | `node scripts/tools/layout-scan.mjs` | manual |
| Accessibility | axe at WCAG A and AA on the main screens against a known list; colour contrast is not checked | UI | `frontend/e2e/a11y.spec.ts`, `frontend/e2e/a11yKnown.ts` | `npx playwright test e2e/a11y.spec.ts --project=chromium` | `e2e-chromium` |
| Release smoke | The built `novira.exe` and `novira-server.exe` start and open the old-data fixture | Build, Shell, Server | `scripts/tools/release-smoke.mjs` | `node scripts/tools/release-smoke.mjs` | `build` (release) |
| Performance measurement | Timings of start-up, commands and IPC, saved and compared against a baseline; no failing budget (partly) | Core, UI, App | `scripts/tools/perf.mjs`, `scripts/tools/perf-startup.mjs`, `backend/crates/novira-core/examples/backend_timing.rs` | `node scripts/tools/perf.mjs all --compare <name>` | manual |
| Dependency audit | Known vulnerabilities in the Rust lockfile and the shipped npm packages | Build | `.github/workflows/audit.yml`, `backend/.cargo/audit.toml` | `npm run audit` in `frontend/` | `audit` |
| Secret scan | Committed secrets and key files left behind (the repository's own scans, no scanner tool) | Shell, Core | `backend/src-tauri/tests/security/secrets.rs`, `backend/crates/novira-core/tests/key_cleanup/` | `cargo test -p novira --test security` | `cargo-test` |
| Security tests | CSP and capability not loosened, no shell launch, no SQL built from values, source scans, panic-safe commands, window setting | Shell | `backend/src-tauri/tests/security/`, `backend/src-tauri/tests/robustness.rs`, `backend/src-tauri/tests/window_config.rs`, `backend/crates/novira-server/tests/auth.rs` | `cargo test -p novira` | `cargo-test` |
| Lint, type and format | Types, ESLint, stylelint, clippy with warnings denied, rustfmt, line ends and the product name | Logic, UI, Core, Server, Shell, Repo | `scripts/tools/typecheck.mjs`, `scripts/tools/check-eol.mjs`, `scripts/tools/check-name.mjs`, `backend/rustfmt.toml` | `npm run check` in `frontend/`, `cargo clippy -p novira-core --tests -- -D warnings` | `static`, `rust-format`, `clippy` |
| Custom lint rules | Layer direction of imports, security patterns in the DOM and the CSP, committed `.only` | Logic, UI, Repo | `frontend/scripts/eslint-layers.mjs`, `frontend/scripts/eslint-security.mjs`, `frontend/scripts/eslint-test-hygiene.mjs` | `npm run lint` in `frontend/` | `static`, `vitest` |
| Docs and manual checks | The map and design pages against the code, test ids and text keys the docs name, the term list, catalogs in every language, manual chapters in step | Repo, UI | `scripts/tools/docs-check.mjs`, `scripts/tools/ui-refs.mjs`, `frontend/scripts/check-glossary.mjs`, `frontend/tests/i18n.test.ts`, `frontend/tests/manual.test.ts` | `node scripts/tools/docs-check.mjs`, `npx vitest run tests/i18n.test.ts tests/manual.test.ts` | `static`, `vitest` |
| Test hygiene | No catch-all folders, no `#[ignore]` outside live tests, no orphan snapshots, no focused tests | Repo, Logic, Core | `frontend/tests/test-hygiene.test.ts`, `frontend/tests/structure.test.ts`, `frontend/scripts/eslint-test-hygiene.mjs` | `npx vitest run tests/test-hygiene.test.ts tests/structure.test.ts` | `vitest`, `static` |
| Test-impact analysis | Picks the checks a change needs from the changed files, then runs them all | Repo | `scripts/tools/affected.mjs` | `node scripts/tools/affected.mjs` (`--list`, `--e2e`) | manual |
| Coverage | Statements, branches, functions and lines of the frontend against floors; lines, functions and regions of novira-core; one combined report (partly: no Rust branches or conditions) | Logic, UI, Core | `frontend/vitest.config.ts`, `scripts/checks/coverage.bat`, `scripts/tools/coverage-report.mjs` | `scripts\checks\coverage.bat` | manual |
| Mutation | Whether the Rust tests notice a changed operator or body; one file at a time (partly: no frontend tool) | Core | `scripts/checks/mutation.bat`, `backend/.cargo/mutants.toml`, `backend/crates/novira-core/tests/mutation_models.rs` | `scripts\checks\mutation.bat rust -- -f <file>` | manual |
| Real-engine run | A job from the queue to the file on a real ComfyUI with no window | Core, App | `backend/crates/novira-core/tests/models_live.rs`, `scripts/tools/models-live.mjs` | `node scripts/tools/models-live.mjs <model>` (GPU lock) | manual |
| Real-app run | The isolated desktop app driven over CDP: IPC, WebView, start-up, the screens' own requests | App, Shell | `scripts/tools/verify-real-app.mjs` | `node scripts/tools/verify-real-app.mjs <test.mjs>` | manual |
| Models sweep | Every installed model: listed, cover loads, offered by its screen, and one real job per kind and base | App, Core | `scripts/tools/models-sweep.mjs` | `node scripts/tools/models-sweep.mjs` | manual |

## Not implemented

Metamorphic tests; race exploration (loom, shuttle) and repeated runs for flaky tests; coverage-guided fuzzing; kill-and-restart at every step; soak and leak checks; load tests of the server; external static analysis, a licence and source check of dependencies and a secret scanner tool; pseudo-localisation; real-engine output comparison; installer tests; Firefox; Miri; formal methods.
