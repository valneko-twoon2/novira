# アシスタントの会話履歴

一覧に戻る: [README.md](README.md)

チャットの前半について、アシスタントに何を伝えるか。訂正（「さっきのままでよかった」）を、直前の答えに上乗せして直すのではなく、元の状態に戻すために使う。アシスタント全体は [01-assistant.md](../01-core/01-assistant.md)。

## 動作

- セッション（`frontend/src/state/agentSessions.ts`）: チャットごとにメッセージのセッションを持つ。テキスト、各回答が行ったことのチップ（`AgentToolLog`）、元に戻したかどうかは実行をまたいで保存する（最大 100 セッション、`PERSISTED_SESSIONS_MAX`）。元に戻すためのスナップショットはメモリ上だけ。
- リクエストは自分のセッションの過去のターンを運ぶ。失敗した返答は除き、新しい方から `CONTEXT_TOKENS`（推定 30000 トークン、約 3 文字で 1 トークン。`frontend/src/state/agentHistory.ts` の `fitHistory`）に収まる分だけ、最新のターンは必ず含める。古いものは丸ごとは送らない。トークン制限が入っている間（メーターのスイッチ。エージェントストアの `tokenLimit`、保存され、最初は入）、収まらないチャットは古いターンを 1 行ずつに縮め（本文の先頭 `DIGEST_LINE_CHARS` の 140 文字、モデル呼び出しなし）、先頭の 1 ターンにまとめる。これは全文のまま残す新しいターンのそばで `DIGEST_TOKENS`（2500）以内に収め、その枠を超える古い行は省いて、ターンに省いた数を書く（`compressHistory`）。収まるチャットは丸ごと送る。制限を切ると、どれほど長くてもチャット全体を送る（モデルが拒否することがある）。同じスイッチは、アシスタントが書くプロンプトも短く保つ。入っている間、`set_generation_settings` は `CLIP_TOKEN_LIMIT`（77、プロンプト欄のカウンターと同じ `estimateTokens` で数える）を超えるプロンプト欄を拒否して何も変えず、`get_generation_settings` はその上限を `promptTokenLimit` として返す（`frontend/src/state/agentTools.ts` の `ToolRun.promptTokenLimit`）。ほかのプロンプト（コミック、メディアのフォーム）は制限しない。`backend/crates/novira-core/src/agent/prompt.rs` の `HISTORY_TURNS`（400）は、非常識なリクエストを止めるだけ。チャットは入力欄の上に推定値を表示する（`ContextMeter`: 次のメッセージと一緒に送る会話と予算の対比、縮めて送る古いメッセージの数、制限のスイッチ）。規則、ツール、現在のリクエストのツールの答えは数えない。新しいチャットは何もない状態で始まる。ツール呼び出しが何かを行った答えは、行ったことを順に書いた括弧つきの注記で終わり（モデル、LoRA とその重み、プロンプト欄、パラメーター、エディター、キューに入れたジョブ、提案した拡張機能）、利用者が元に戻した場合は 2 つ目の注記が付く（`frontend/src/state/agentHistory.ts` の `historyTurn`）。
- 過去のターンの画像: 画像そのものは再送しない。画像を運んだターン（利用者の添付、答えが見せた試し描き）は、その名前を書いた注記で終わり、規則は、リクエストがその画像に関するとき `view_picture` に名前を渡して見直すようモデルに指示する。そのため添付した元画像は最初のターンのあとも忘れられない。見直しは、ほかと同じく読み取り許可のもとで求める。
- 以前の設定: セッションの過去の答えのうち Generate タブを変えたものそれぞれについて、変更前の設定（元に戻すスナップショット: モデル、LoRA、プロンプト、ステップ、CFG、サイズ、スケジューラー、シード）を、それを招いた利用者の依頼（300 文字に切る）と元に戻したかどうかを付けて、古い順に最大 8 件（`earlierSettings`）。変更のあとで失敗または停止した答えも数える。
- `get_generation_settings` はそれらを `includePrompts` があるときだけ `earlier` として返すので、プロンプトと同じ質問のもとで読まれる。なければ送られない。
- 規則（`INSTRUCTIONS`、短くは `COMIC_INSTRUCTIONS`）は訂正の扱い方を定める。「前は良かった」と言われたら `earlier` から一語一句そのまま復元する。依頼が指す人や物だけを変える。人物ごとの語と共通の語を分け、ネガティブな語が他から何を奪うかを確かめる。矛盾する語、重複する語、効かない語は積み上げずに置き換え、プロンプトの長さがどう変わったかを伝える（`set_generation_settings` は `tokens` を返す: リクエスト前と今の `estimateTokens` の推定値）。訂正に失敗したあとは、上に直さず利用者の依頼から作り直す。不具合が直ったとは決して言わない。利用者が画像を添付しない限り、アシスタントはエンジンが作った画像を見ないため。

## 境界

| 境界 | 防ぎ方 |
|---|---|
| 過去のプロンプトがモデルに届く経路 | `includePrompts` 付きの `get_generation_settings` だけ。これは読み取り許可が必要で（`is_read_gated`、`isReadGated`）、現在のプロンプトと同じく利用者に尋ねる |
| 保持するもの | 以前の設定は元に戻すスナップショットから来て、これはディスクに保存しない |

## 既知の限界

- アプリを再起動すると、古いチャットの以前の設定は失われる（スナップショットはメモリ上にあった）。各答えが行ったことの注記は残る。
- 以前の設定は Generate タブだけが対象。エディター（コミック、テキスト、ワークフロー、メディアのフォーム）では、モデルは注記を持ち、エディターの現在の状態を読む。
- 注記が書くのは答えが行った変更の種類で、その語ではない。語は `earlier` にある。
- モデルが規則に従うかどうかはテストしていない。テストが確かめるのは、規則とデータがあること。
