# Models

The models feature keeps the model files that ComfyUI loads (checkpoints, LoRAs, VAEs, ControlNets, upscalers, diffusion models) and, with [model-packs.md](model-packs.md), the extra model packs that some kinds of media need. It lists the files on disk, classifies each one, installs new files from a source, and holds the keys for Civitai and Hugging Face. Searching those two sites (the Browse tab) is on [browse.md](browse.md).
## Behaviour

- **Folders.** The first model root is `<data>/models`; the folders in `modelRoots` (`settings.rs`, at most 16) follow and are all scanned at start. ComfyUI folder names (`checkpoints`, `loras`, ...) and Stability Matrix names (`StableDiffusion`, `Lora`, `LyCORIS`, ...) are both recognised (`models/layout.rs`). A file is a model when its extension is `safetensors`, `ckpt`, `pt`, `pth`, `bin`, `gguf` or `sft`.
- **ComfyUI paths.** The roots and the pack sections (the data folder's, and for each further root the pack folders that exist there as `novira_<kind>_<n>`) are written to `<data>/extra_model_paths.yaml` at start, so an owned ComfyUI lists the same names. With an external ComfyUI (`comfyuiUrl`) the user configures equivalent paths. Before a job runs, the engine checks that ComfyUI lists every model the job names and otherwise fails with a readable reason (`check_models`, `comfy/client.rs`).
- **Kind and base.** A scanned file takes its kind from its folder. An install takes the kind from the starter entry or the user's choice, then the safetensors header (tensor names), then the type the site declares (remote files), then the file name (`classify::kind_from_name`: `.pth`, `.gguf`, and words such as `lora`, `vae`, `umt5`). The header tells a checkpoint (it carries its own VAE and text encoders) from a diffusion transformer on its own (`diffusion_models`), a text encoder (`text_encoders`), a VAE, a LoRA, a ControlNet, an IP-Adapter, a CLIP vision model, an ESRGAN-style upscaler and a model patch (`model_patches`: Anima LLLite, the Qwen-Image and Z-Image Fun ControlNets, told apart by the tensors ComfyUI's `ModelPatchLoader` reads). The family of a diffusion transformer or a LoRA is read from its tensor names (`classify::detect_architecture`): Flux, FLUX.2, Chroma, Anima, Qwen-Image, Z-Image, HiDream, AuraFlow, SD3, HunyuanImage, Hunyuan-DiT, Wan, HunyuanVideo, HunyuanVideo 1.5, LTX-Video and LTX-2; a GGUF takes it from its name. Variants of a family (Flux Fill and Kontext, Qwen-Image-Edit, Wan VACE and the Wan models that need other inputs) are told apart when the job is built, from the tensors or the name (`classify::detect_variant`). A LoRA's family tensors win over its metadata, since trainers write wrong architectures (sd-scripts' Anima trainer writes `stable-diffusion-v1/lora`); an Anima LoRA that leaves the LLM adapter alone is told by its Cosmos blocks (`adaln_modulation_self_attn`). The base of other kinds comes from the header: `modelspec.*` and `ss_base_model_version` metadata (a newer family's name in the latter counts), then tensor names, then the file name. Only the header is read, never the weights. At start, checkpoints under `<data>/models` whose header names another kind move to that kind's folder (`layout::move_misfiled`). The Generate tab runs SD 1.x, SD 2.x and SDXL checkpoints, the checkpoints of Hunyuan-DiT, and the diffusion models and checkpoints of Anima, Flux, FLUX.2, Chroma, Qwen-Image, Z-Image, SD3, HiDream, AuraFlow and HunyuanImage with the text encoders and VAE it finds among the installed models (generation.md); the worker refuses the other bases with a message naming the base (the workflow editor can use them through ComfyUI's own loader nodes).
- **Records and keys.** A model's key is a hash of its folder and ComfyUI name (`registry::key_for`), so it survives rescans. A rescan keeps the stored record with the user's edits and refreshes the file facts when size or path changed. Once per fix of the LoRA detection (`LORA_BASES_CHECKED_META` in `service/mod.rs`), the start re-reads the headers of LoRAs stored with an SD base and moves those whose tensors name a newer family (`registry::corrected_lora_bases`); after that a base the user sets stays. Records stored as `any` get the same once-only check (`registry::corrected_any_bases`). `update_model` ignores patches to `key`, `path`, `size`, `comfy`, `type` and `format`.
- **Installed list.** `bootstrap` returns the installed models. An install adds its record and emits `ModelAdded`; each job's status (waiting, downloading, running, completed, cancelled, error) goes out as `ModelInstall` events.
- **Covers.** A card shows the record's picture (from the Civitai lookup or an install), an icon for kinds without pictures, and the same icon when a picture kind has none. With `civitaiLookup` off, a file put in a folder by hand gets no picture by design, so the Models screen shows one note above the grid (`CoverHint`) whenever the lookup is off and at least one model of a picture kind has none; its button opens Settings on the Engine tab. The note is not drawn on cards.
- **Pictures and the original page.** The record keeps every picture of the Civitai version (`coverImageUrls`, the cover first, at most eight, none when there is only the cover) and the model's own page (`pageUrl`: `civitai.com/models/<id>?modelVersionId=<id>`, or the `huggingface.co/<repo>` of a Hugging Face install). Both are filled at install and by the hash lookup (`covers_checked_4` asks again once the models that had a cover but no page). The detail panel pages through the pictures and lists the page as a link; opening it goes through `openSourcePage`, which accepts only https addresses on the model sites. A model without a known page shows no link.
- **Delete.** A file under `<data>/models` is deleted. A file in any other root is only hidden, until the same file is installed again.
- **Folder scan.** `scan_folder` takes no argument: the shell opens a native folder dialog itself (`backend/src-tauri/src/commands.rs`, `backend/src-tauri/src/dialogs.rs`; the reply is `null` when the user cancels), lists the model files in the chosen folder and marks those already installed (same path, or same name and size). It installs nothing. The shell remembers the paths it found (`ScannedModels`, replaced by every scan); they are the only local paths `install_model` accepts. The screen has a button, not a text field.
- **Install sources.** `install_model` accepts only these forms, parsed strictly by `models::install::parse_source` before anything is written:
  - `civitai:<model>/<version>-<file>` (the Browse tab);
  - `https://civitai.com/models/<id>[?modelVersionId=<v>]` (the given version, else the first; the primary file, else the first);
  - `owner/repo::path` on Hugging Face (one model file of a repository);
  - another `https` address, or `http` only for `localhost`, `127.0.0.1` and `[::1]`;
  - an absolute path to a model file on this PC, only one the last folder scan listed: the command refuses any other local path (`source_is_allowed`), so the page cannot make the backend read a file it typed. The URL tab (`InstallFromSource.tsx`) therefore does not send a drive, share or absolute path: it points to Scan Folder; a failed install keeps the typed text, and the Scan Folder tab shows a failed scan and says it needs the desktop app on the browser server.

  A bare `owner/repo` is refused as a diffusers-format repository.
- **Local files** are hard-linked into the kind's folder when possible, otherwise copied (`install::link_or_copy`). A file of the same name already there is refused.
- **Remote downloads.** The file name is checked first (`safe_file_name`: model extension, no leading dot, no separators, control characters or Windows device names, at most 200 characters). Bytes go to `<data>/models/.downloads/<job>.part` and move into place when complete. A download fails after 60 seconds without data, or when it ends before the announced size. A stopped download keeps its `.part` and a `.resume` record; `download_with_stall` asks for the rest only, with `Range` and `If-Range`. The part is named by the source (`install::part_name`: a hash of the source text), not by the job, so an install of the same source started again continues the part and record of the stopped one. Two installs of one source never run at once: the second is refused while the first is waiting, downloading or running. Partial files are listed and deleted in Settings → Data (`unfinished.rs`).
- **Keys and token.** The Civitai key and the Hugging Face token are entered in Settings (`CivitaiKeyControl.tsx`; `set_civitai_key`, `set_hf_token`) and stored encrypted in `<data>/secrets/civitai.key` and `huggingface.key` (`secret.rs`). The screens only learn whether one is set. A plain `civitaiApiKey` in `settings.json` is a fallback for the Civitai key while no saved key exists; clearing the saved key drops that fallback until the next start.
- **Where the keys go.** The Civitai key goes to Civitai's API (search, model, version, licence and cover lookups) and to the download address the API returns, which must be `https` on `civitai.com` or a subdomain (`is_civitai_download`; in a debug build that points the API at a fake server on this PC, that server's own address too); any other address in an answer is refused with "unexpected download address", and no key is sent. A direct URL gets it only over `https` on `civitai.com` or a subdomain. The Hugging Face token goes to Hugging Face's API (search, listing, covers, licences), to `huggingface.co` downloads, and to the voice pack's downloads (see media-generation.md). Other packs send no token.

## Boundaries

| Boundary | Guard |
|---|---|
| Model downloads | Sources are parsed strictly (`models::install::parse_source`): `https` only (plain HTTP only for this PC), Hugging Face repository and path made of plain name parts, no path part made only of dots. File names are checked (`safe_file_name`: model extensions only, no control characters, no Windows device names) before anything is written. Listing a Hugging Face repository's model files (`list_hugging_face_files`) takes the plain `owner/name` (checked as above), asks `/api/models/<repo>` with the token when one is set, and keeps only the single model files; it downloads nothing. In a debug build only, `NOVIRA_TEST_<SERVICE>_BASE` may point a service at `http://127.0.0.1:<port>` or `http://localhost:<port>`; other values are ignored, and the checks for real hosts stay. |
| Secrets in transit | The keys are sent as a bearer header, never in a URL, and only to the places listed under Where the keys go. A direct URL gets a key only over `https` on the owning site or a subdomain (`host_is`); a host that merely contains the site's name does not. A download address returned by the Civitai API must pass the same test (`https` on `civitai.com`), or the install is refused. The HTTP client drops credentials on a redirect to another host. |
| Secrets at rest | Encrypted with Windows DPAPI (current user, with an application-specific entropy), stored under `novira-data/secrets/`. Never returned to the frontend: it can only ask whether one is set and replace or remove it. |

## Known limits

- DPAPI protects against other Windows users, not against another program running as the same user.
- A model file is data for ComfyUI's loaders; `.ckpt` / `.pt` files can contain pickled code, which is why `.safetensors` is preferred and pickle-format files should come from trusted sources. The inpaint pack's `big-lama.pt` is such a file.
- The Civitai lookup of local models (`civitaiLookup`, off by default) sends the SHA-256 of each model file to Civitai, and the Civitai key with it when one is saved. Turning it on is the user's consent; it applies at the next start.
- Unfinished downloads stay on disk until the user deletes them, since a stopped download keeps its part and `.resume` record. A part another program has open may not be removable; it then stays in the list (ComfyUI's downloads are listed too; see extensions.md).
