# 候補と下書き

一覧に戻る: [README.md](README.md)

候補ビュー（画面の名前は「候補」。内部の識別子は `drafts` のまま）には、二つが並ぶ。生成タブの Invoke で作った絵（生成の組）と、下書きの組である。後者は、同じ設定でシードだけ違う多くの候補を途中までしか描かず、有望なものを選んでそれだけを最後まで描けるようにする。普通のキュージョブ（[01-generation.md](01-generation.md)）に下書きの位置を付けたもの。

## 動作

- 下書きは `draftAt`（0 から 1）を持つ、テキストから画像か画像から画像のジョブ。グラフは `KSamplerAdvanced` で、開始から `draft_step(N, f) = clamp(round(f * N), ceil(0.2 * N), N - 2)` ステップ後に `return_with_leftover_noise: disable` で止まる。SD ファミリーと、共通グラフ上のすべての新しいファミリーで同じ（`backend/crates/novira-core/src/comfy/graph.rs`）。FLUX.2 は代わりにそのステップでシグマを切る（[03-model-families.md](03-model-families.md)）。ステップは 4 以上が要り、高解像度修正はなし（下書きは省き、仕上げの実行が保つ）。結果は中間画像として保存する。
- 画像から画像は、KSampler がそのノイズ除去 `d` で作るスケジュールをサンプリングする（`draft_schedule`: `int(N / d)` ステップで、`int(N / d) - N` から始める。0.9999 を超えると 0 から全体）。そのため下書きは仕上げの実行の始まりで、位置は実際に描いたステップの割合になる。強さ 0 は断る。インペイント、アウトペイント、アップスケールは下書きを断る。
- 編集モデル（Flux Fill、Flux Kontext、Qwen-Image-Edit）は下書きを断る。下書きビューは、生成タブの画像モデル（`drawableModels`）から編集モデル（`draftRefusal`。バックエンドが読むファイル名の語）を除いたものを出し、除いたものを名指しする。
- `frontend/src/state/drafts.ts` はセッションを保つ。候補は 1 から 24（設定 `draftCount`）、シードはランダム、ステップの 0.25 から 0.6 まで描く（設定 `draftPosition`、パーセント）。生成タブの依頼（`buildRequestFor('generate')`）から作り、ビューで別のモデルを選んだときはそれを使う。画面の枚数と位置（`state/draftForm.ts`）は、設定されるまで設定に従う。セッションは依頼の参照画像と、画像から画像ではキューが返した保存済みの元画像（`initImageUrl`）を保ち、仕上げと再試行はそれらをもう一度送る。
- 続きを描くは、そのシードで通常の実行を 0 ステップ目からキューに入れる。仕上げの画像が失敗、キャンセル、削除された候補は、もう一度仕上げられる（`canFinish`）。失敗した下書きは同じシードで再試行する。候補の印（`mark`、`verdict`）はストアに残るが、画面は使わない。
- 描いている最中の候補は、右のギャラリーのグリッドと同じに、途中の絵とステップ数を見せる（`Cell.tsx`。下書きの段階も、仕上げの段階も、生成タブの組も同じ）。キューの進捗（`useQueue.progress`）のうち、自分の項目のものだけを使う。仕上げの最中は、元の下書きより途中の絵を優先し、終われば下書きに戻る。進捗は実行中の 1 件だけなので、待っている候補は待ちのまま。組は、キューへの登録が返ってから作る（または書き換える）ので、その時点のキューの状態を当てはめる（`withQueue`）。空いたキューはその前にジョブを始めていて、次にキューが変わるのは完成のときなので、当てはめないと描いている間ずっと「待ち」と出る。キューがまだ知らない項目は、元の状態のままにする。
- セッションはローカルストレージ（`novira.drafts`）にある。

### 画面

- 組はタブにせず、決めることが残る組（`flow.ts` の `flowGroups`。生成の組は残っていれば全て、下書きの組は完成画像がギャラリーにない候補を持つもの）を 1 本の一覧に新しい順で出す。最初は 8 組（`FLOW_GROUPS`）で、末尾のボタンで 8 組ずつ増やす。履歴で開いた組（`currentId`）は、決めることがなくても出し、見える位置へスクロールする。全ての組は上のバーの時計のボタン（数は組の数）で開く履歴（`DraftHistory.tsx`）にある。
- 組の見出しは、時刻（今日でなければ日付つき）、モデル、プロンプトの始め（1 行、全文はツールチップ）、枚数、失敗した下書きの再試行、✓（組の全て: `isAcceptable` なものを `adopt` か `finish`）、✕（`closeGroup`）。
- セルは状態（待ち、描画中とステップ、失敗、下書きの組の完成）だけを絵の上に小さく出す。描き終えた下書きと生成の組の絵には語を出さず、シードと下書きの位置はツールチップにする。ホバーかフォーカスで、下に ✓（生成の組は `adopt`、下書きは `finish`）と ✕（`discard`）が出る。ホバーのない画面（タッチ）では常に出る。
- クリックは 1 枚を選び（選んでいる 1 枚なら外す）、Ctrl で足し引き、Shift で一覧の順の範囲（選べるものだけ。`rangeOf`）、Space で足し引きする。選びは組をまたいでよい。選んでいるときだけ下にバーが出て、枚数、✓（組ごとに `adopt` か `finish`）、✕（組ごとに `discard`）、選択の解除を並べる。
- 上のバーは、「下書き」ボタン（下書きの欄をポップオーバーで開く。始めたら閉じる。`DraftForm.tsx`）、「ボード」の欄（`BoardPicker.tsx`。押すと、ギャラリーのボード欄と同じくツリーで、カバー（いちばん新しい絵）と枚数つきで並べ、名前とパスで探せる。折りたたみは使わず全て開き、アーカイブしたボードは選んでいるときだけ出す。ギャラリーの `selectedBoardId` をそのまま見せて変える。`selectBoard` なので、ギャラリーの選択も変わり、ギャラリーの設定「クリックしたボードに自動追加」（`autoAssignBoardOnClick`）がオンなら生成の保存先も変わる）、絵の大きさのスライダー（`draftForm.ts` の `thumbSize`、保存しない。幅 720px 以下では出さない）、履歴のボタン。
- ダブルクリックか Enter で、画面の中の大きな表示（`LargeView.tsx`）になる。絵のある候補だけを一覧の順にたどり、← → で前後、Enter で ✓、Delete（Backspace）で ✕、どちらもそのあと次へ（一覧から外れる操作で末尾なら一つ前、何も残らなければ一覧へ）、Esc で一覧へ戻る。キーは表示の要素が持つフォーカスにだけ効き、ウィンドウには付けない。下の帯に残りの絵を並べる。表示中の絵がほかの操作で消えたときは、同じ位置の絵に替わる。描き終えた絵はビューアと同じ `ZoomableImage` で拡大・移動でき（ホイール、右下の倍率、拡大のキー。拡大のキーと Space の手のひらはビューアと同じくウィンドウに付き、大きな表示が開いていればフォーカスの場所を問わず効く）、次の絵は全体表示に戻る。描いている途中の絵は進み具合をそのまま出す。表示中の候補は `useDrafts` の `viewing`（保存しない）が持つので、ビューアへ切り替えて戻っても大きな表示のまま（一覧の件数を超えた組の絵でもその組を出す。戻ったときに絵がもう無ければ一覧に戻る）。一覧へ戻るときは、見ていた組が一覧に残るよう、出す組の数を 8 組単位で増やす（`limitShowing`。減らさない）。
- スマートフォンの画面（`onOpen`）は大きな表示を使わず、各絵の開くボタンとダブルタップで自分の全画面表示を開く。
- 候補を捨てる（`discard`）は、その候補の待っている・描いている項目（下書きと仕上げ）を取り消し、生成の組なら、ボードに入っていない画像を `closeGroup` と同じくゴミ箱へ送る（取り消しの項目つき）。下書きの組の画像は、組を閉じるときと同じく消さない。候補は組から外れ、空になった組は閉じる。

### 生成の組（通常の生成）

- 設定「生成した絵をまず候補に置く」（`newPicturesToCandidates`、初期値はオン）がオンのとき、生成タブの画像フォームの Invoke は宛先 `candidates` で積む（`enqueueActive` が `held` をビルダーへ渡し、`buildGenerateRequest` が宛先を決める。`buildRequestFor` やプリセットの実行、比較グリッドは `gallery` のまま）。バックエンドは、その画像を `isIntermediate` つきで、ボードを覚えたまま保存する。ほかの画面、動画、音楽、音声、コミックは対象外。
- 1 回の押下は `kind: 'generation'` の 1 つの組になる（`addGeneration`。動的プロンプトの追加の組もまとめる）。候補は途中の絵を持たず、`finalItemId` で完成までを追う。絵ごとのプロンプトが違ってよいので、`params` は最初の絵のもの。Invoke を押したとき、スタート画面なら候補ビューへ切り替わる。
- 画像は `wiring.ts` で `image_added` を受けても、ボードやビューアを動かさない（下書きと同じ）。完成した絵を選ぶ・ダブルクリックでビューアに出すのも下書きと同じ。設定「完成した画像をビューアに表示」は、ボードへ直接入る絵だけに効く。
- ✓（`adopt`。ボタンにボード名は書かない）は、完成画像の `isIntermediate` を外し、そのときギャラリーで選んでいるボード（`selectedBoardId`。「ボードなし」を選んでいるとき、選んだボードが無くなっているときは未分類）へ移して、その候補を組から外す。組を作ったときのボード（`boardId`）は使わない。セルを右のボード欄へドラッグしても同じ（`moveImagesToBoard` も `isIntermediate` を外す）。ドラッグで入れた絵は、ギャラリーに出た時点で組から外れる（`dropAdopted`。最後の 1 枚なら組も閉じる）。
- 組の見出しや履歴の ✕（`closeGroups`。生成の組に「残りをゴミ箱へ」のボタンはない）は、待っている・描いている項目を取り消し、ボードに入っていない画像を見える状態に戻してからゴミ箱へ送り、削除の取り消しの項目にする。取り戻した画像は、もとのボードに戻る。画像が隠れたまま残らないための動き。
- 履歴は下書きの組と同じ画面に出る。生成の組は「○ 枚」と数え、設定の再利用で生成の欄へ戻せる。

## 境界

| 境界 | 守り |
|---|---|
| キューへ送る依頼 | ほかの生成ジョブと同じ検査。下書きの位置とステップ数は、グラフの組み立て時にもう一度検査する |

## 候補とキュー項目の結びつけ

候補は自分のキュー項目を ID で名指しする。バックエンドは ID を二度与えない（meta テーブルの `queue_next_id` が、キューを空にしても再起動しても残る。それ以前は、キューが空になると ID が 1 から振り直された）。`syncGroups` は、シード、下書きの位置（下書きは持ち、仕上げの画像は持たない）、時刻（バッチを始める 60 秒前より後）が合うときだけ、項目を候補のものとして取る（`isItemOf`）。ID を使い回した版が保存したバッチは、ギャラリーとバッチの両方が揃った時点で一度だけ直す（`repairStored`。済んだことは保存する `picturesRepaired` が覚える。絵の設定を読めなかったときは済んだことにせず、次の機会に回す）。まず候補の画像の設定だけを読み、誤った画像があるときに限って全画像の設定を読んで、見つけ直す（`repairGroups`）。直している間に始めたバッチはそのままにする。自分の設定が別のジョブのものだと示している画像は、シード、プロンプト、モデル、時刻で見つけた候補自身の画像に置き換えるか、手放す。設定をまだ読んでいない画像は触れない。

## 既知の限界

- 入れ先のボードは生成の組の ✓ にだけ効く。下書きの仕上げは、組を作ったときのボード（`boardId`）へ入る。
- 生成の組は、このページのローカルストレージ（`novira.drafts`）にある。別のページ（LAN や外出先の画面）で押した Invoke の絵は、そのページの組になり、このページの候補ビューには出ない。
- 失敗した生成の組の絵は、再試行できない（もう一度生成する）。
- 続きを描くは画像全体を 0 ステップ目から描き直すので、通常の実行と同じ時間がかかる。
- セッションは元画像を URL で名指しする。その画像が削除されると、元画像のないジョブと同じく、仕上げは失敗する。
