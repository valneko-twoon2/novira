# テキスト: 文字を AI で仕上げる

一覧に戻る: [README.md](README.md)

テキストタブは文字と吹き出しを自分で描く（ベクター、編集可能）。左の列の AI の欄は、1 つの文字レイヤーの文字を画像から画像への実行で塗る。実行ボタンは生成画面と同じ「生成」（`params.invoke.invoke`、Lightning アイコン）で、その上のシードの行も同じ部品（`SeedControl`）である。金、炎、氷などである。置き換えるのは文字の塗りだけで、輪郭、2 つ目の輪郭、影はその上からレイヤーのスタイルどおりに描かれる。出力は SVG ではなく画像で、モデルが一度描いた文字の画像なので、あとから文字としては編集できず、文字を変えて画像を作り直すことだけができる。

## 動作

- **場所。** `RichSection.tsx` は、テキスト画面の左の列の先頭、テンプレートのカードの下にある。上から、シードの行、実行ボタン（「生成」、候補の数、停止）、モデル、質感と追加の語、折りたたみの「生成の詳細」（強さ、はみ出し）。候補はキャンバスの下のストリップにある（`TextCandidates.tsx`）。レイアウトは [04-text-screen.md](04-text-screen.md)。実行は文字レイヤーを待つ。吹き出しを選んでいるか何も選んでいないとボタンは無効で、注記が理由を示す。設定（`useRichForm`、キー `novira.textRich`、ほかのページに即時に反映）は、質感（`richLooks.ts`。金、炎、氷、ネオン、石、キャンディ、クローム。選択中のものを押すと解除）、追加の語（英語のタグ）、モデル（おまかせ、または絵を描けるモデル）、強さ 0〜100、はみ出し 0〜100、1 回の押下で作る候補の数（1〜4）、シードの行（`SeedControl`。生成画面と同じ）。ランダムは実行ごとにシードを引いて欄に残し、固定は最初の候補にそのシード、次の候補ごとにシード + 1 を与える。
- **実行**（`richRun.ts`、`runRich`）: 文字を、レイヤーのフォントサイズで白く、枠の中に描く（`render.ts` の `drawWhiteGlyphs`）。枠（`richFrame.ts`）は、文字の広がりにフォントサイズの半分の余白を足したもので、縦横比は 1:3〜3:1 に保ち、辺は 16 の倍数、512 以上で、モデル自身の面積に近づける。`richPixels.ts` が文字から、光を当てたベース画像（`bevelBase`。質感の色で文字を、その地色の上にエンボスしたもの）と、線の ControlNet があるときは文字の輪郭の画像（`lineMap`）を作る。どちらも非表示のコントロール画像としてアップロードし、実行が終わると削除する。候補ごとに、画像から画像へのジョブを 1 つキューに入れ（`buildRichRequest`。origin `generate`、宛先 `intermediate`、LoRA なし、VAE の上書きなし、モデル自身のステップ、CFG、スケジューラー）、`runJob` で待つ。結果は切り抜き（`cutPicture`）、非表示の画像（`isIntermediate`、カテゴリ `general`）として保存し、元の結果は削除する。候補は 1 つずつ順に作るので、キャンセルは残りを止め、各候補は準備できしだい現れる。
- **どのモデルか**（`richPlan`）: 選んだモデルがインストールされていればそれ。なければ、線の ControlNet（`poseSkeleton.ts` の `pickLineModel`。線画またはキャニーの名のもの、なければユニオン型）が系統に合うときは生成タブのモデル。それもなければ、それを持つ別の絵を描けるモデル（SDXL 優先）。それもなければ ControlNet なしの生成タブのモデル。ControlNet があるとき、強さは denoise 0.60〜1.00 に対応する（ネットが文字を保つので強い描き直しでも安全）。ないときは 0.35〜0.55 で、セクションが控えめな生成になると示す。
- **切り抜き。** はみ出し 0 では画像のアルファは文字のアルファとぴったり一致する。はみ出しを与えると、背景（4 隅の中央値）に似ていないものが文字の外に残り、画像の短辺の最大 12% の距離で薄れる（炎、光）。きれいな背景では何も足さない。
- **レイヤー上。** `TextLayer.rich`（`textModel.ts` の `RichFill`）: 画像、候補（新しい順、最大 12）、作ったときのフォントサイズで覆う範囲（レイヤーとともに拡縮するので、サイズ変更で新しい実行は要らない）、`sourceKey`。`richSourceKey` は文字の形を決めるもの（テキスト、フォント、太さ、行の高さ、揃え、縦書き、曲げ、フォントサイズに対する字間を 2% 刻み）を含み、色、位置、回転、不透明度、サイズは含まない。レイヤーのキーが異なるあいだ、キャンバスは通常の塗りを表示し、ストリップが新しい実行を勧める。編集を元に戻すとジョブなしで画像が戻る。実行の最初の画像は、元に戻す 1 ステップ（チェックポイントのあとライブ更新）。候補の選択と通常の塗りへの復帰は、それぞれ 1 ステップ。
- **描画。** `renderScene` は読み込み済みの画像を受け取る（キャンバスは `richPictures.ts` の `useRichPictures`。`saveScene.ts` はそれを待つので、保存された画像には必ず AI の塗りがある）。画像がない、または読めないときは通常の塗りになり、エラーにはならない。当たり判定と選択枠は文字の箱のまま。
- **失敗。** エンジンのメッセージつきのトースト（`text.rich.failed`）。レイヤーは変わらず、非表示の補助画像は削除する。キャンセルは通知なし。レイヤーごとに同時に 1 回の実行。

## 境界

ジョブは、アプリ自身のパラメーターを持つ通常のキューの項目で、ほかと同様にバックエンドが検査する（[01-generation.md](../01-pictures/01-generation.md)）。画像はバックエンドが保存し、レイヤーに届くのは名前だけ。PC の外には何も出ない。

## 既知の限界

- 画像は非表示のギャラリー画像: 設定の「中間画像を消去」で削除され、レイヤーは通常の塗りになり、新しい実行を勧める。
- モデルは文字の中に好きなものを描く（漢字の隅に紋章が出ることがある）。候補が複数あるのはそのため。
- 線の ControlNet がないと強さの上限が低くなり、質感は穏やかになる。
- 削除された Logo 画面で作った古い画像は今も開けるが、この機能はそれを読まない。
