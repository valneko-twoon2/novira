# コミックのページレイヤー、ペイント、インペイント

コミックのページは、レイヤーをキャンバスのレイヤーとして持ち、キャンバス自身のツールでその上に描き、インペイントで自分の一部を描き直せる。レイヤーを収める文書とその保存は [01-comic-canvas.md](01-comic-canvas.md) に、コマの描き方は [01-comic-drawing.md](../02-drawing/01-comic-drawing.md) にある。

## 動作

- ページは `canvas` を持つ。レイヤーはページのピクセル単位（200 dpi、`pagePixels`）のキャンバスエンティティと生成ボックスで（`state/comic/pageCanvasDoc.ts`）、キャンバス文書の保存形式（`state/canvasDocument.ts`）に従う。画像はギャラリー名で持ち、ページの中にしかないときは非表示のギャラリー画像として保存する。ラスターは下から順に並び、スロットレイヤー `panels` と `balloons` が必ず 1 つずつある。これらはコミックが描くもので、オブジェクトを持たず、削除・描き込み・複製・変形・結合はできないが、表示・非表示・ロック・透明度・ブレンド・移動はできる。マスク（インペイント、領域）はラスターの上に置き、ページの絵にも PSD にも含まれない。読む・編集する・保存するときの上限は、1 ページにラスターレイヤー 32 枚（スロット含む）、マスク 8 枚、1 レイヤーにオブジェクト 5000 個、1 ページに座標 300000 個。座標はページから 100000 ピクセル以内に収める。`canvas` のないページには 2 つのスロットとページ全体のボックスが付く。
- version 1 の文書（コミック固有の以前のレイヤースタック `layers`：コマ、吹き出し、ベクター描画、置いた画像）は読むときに移行する（`migrateLayers.ts`、`layersV1.ts`）。ストロークはストロークオブジェクトに、画像レイヤーは画像オブジェクトになる。回転・反転した画像は、ギャラリーを読み込んだ後に 1 回だけ、新しい非表示の画像に焼き込む（`bakeRotation.ts`）。それまでと、画像を焼けなかったプロジェクト（トーストで知らせる）では、プロジェクトを書かず、version 1 の文書を残す。移行後の最初の保存で version 2 を書く。
- 開いたページごとに専用のキャンバスストアがある（`state/comic/pageCanvas.ts`、最大 8 個まで保持）。`page.canvas` が正本で、ストアの変更は最初の 1 回はすぐ、その後は最短 150 ms 間隔で書き戻す。ページが外から変わったとき（アシスタント、読み直したプロジェクト、別の用紙に戻すコミックの元に戻す）は、ストアを読み直し、元に戻す履歴を消す。ストアは上限を超えるレイヤーやオブジェクトを、メッセージを出して拒む。コミックの元に戻す・やり直しはレイヤーに触れない（`history.ts` はページの現在のレイヤーを保ち、用紙が変わるときは拡縮する）。ストア自身の元に戻すは触れる。
- コミック画面のページは、ページモードかペイントモード（`state/comic/paintMode.ts`、ツールバーの切り替え）にある。ペイントモードでは、キャンバスのツール（ブラシ、消しゴム、モザイク、矩形、投げ縄、移動、ボックス、スポイト、塗りつぶし、ラスターのフィルター）が、ページの上に重ねたステージを通して、選んだラスターレイヤーに描く。ページのストアはブラシで始まる。そのバーには表示ツールがなく（ページが自分で表示を動かす）、キャンバスのタブは表示ツールで始まって、最初の押下では表示だけが動き何も描かないため。ツールはどちらでも保存しない。スロットを選ぶ、Escape（待機中のインペイント結果を捨てた後）、別のページへ移る、コミックを離れる、のいずれかで終わる。キャンバスのレイヤーパネルは、右列のタブの下に、開いているページのストアで常に表示する。
- ページのインペイント（`app/pageInpaint.ts`、`state/comic/pageInpaint.ts`、ペイントツールバーのボタン）：キャンバス自身のリクエストビルダーがページのストアで動く。初期画像は、描かれたままのページ（コマ、吹き出し、ユーザーのラスター）を生成ボックスで切り出したもので、マスクはストアのインペイントマスクから作る。ページ上のボックスはページの内側にあり、1 辺 64〜2048 ピクセル、かつ 1536 x 1536 ピクセル以下。これを超えるボックスは、先にマスクの周りに合わせ、ユーザーに知らせる。キューに入れた項目はページと結び付けて覚え、結果は依頼したページのストアに仮置きする（別のページが開いていても同じで、その場合は通知を出す）。キャンバスの仮置きバーで、新しいラスターレイヤーとして受け入れる、ギャラリーに残す、捨てる、のどれかを選ぶ。マスクがないとき、モデルがないときは何もキューに入れない。
- アシスタントはページのラスターレイヤーを見る（`layerContext`：下から 1 の番号、名前、種別 `panels`・`balloons`・`raster`、表示状態、違うときはロック・不透明度・ブレンド・オブジェクト数）。ペイントの状態（`paintContext`：ページに描いているか、最大レイヤー数、現在の枚数）も見る。操作は `layer`（名前、表示、ロック、不透明度、ブレンド、上下・最上・最下への移動）、`addLayer`（空のラスター）、`deleteLayer`（ロックされていないユーザーのラスター）で、ほかのコミック操作と同じように検査する（`state/comic/layerAgent.ts`）。レイヤーに描くことも画像を入れることもできず、スロットは削除できない。アシスタントによる変更は、まずユーザーが描いたものを書き、次にページのストアにページを読み直させ（履歴は消える）、描いていたレイヤーがなくなればペイントモードを抜ける。
- 保存するページ、PSD、サムネイルは、ラスターをその順序で描く（`features/comic/pageRender.ts` の `pageGroups`）。ページは画像を並行して読み込んで準備し、画面ではレイヤーを積み重ねた箱として描く（`features/comic/layers/PageLayers.tsx`）。そのキャンバスは、そのレイヤー自身の画像が変わったときだけ描き直す。

## 境界

| 境界 | 防ぎ方 |
|---|---|
| 保存したページの `canvas` | 読むときは入力として扱う（`parsePageCanvas`）。すべてのフィールドを検査し、未知の種別・壊れたエンティティとオブジェクトを捨て、スロットを戻し、上記の上限を適用する。壊れた文書や大きすぎる文書で失うのは壊れた部分だけ。画像は保存名のギャラリー画像からしか取らない。 |
| ページのストアへの追加 | 上限を超えるレイヤーやオブジェクトは拒み、知らせる。保存時に黙って捨てるようなものは受け入れない。 |
| アシスタントのレイヤー操作 | 誤った番号・種別・値は飛ばす。ロックされたレイヤーとスロットは削除しない。 |

## 既知の限界

- 図形レイヤーとスクリーントーンレイヤーはない。
- 描いたレイヤーが多いページは、コミックプロジェクトの 32 MiB の上限に近づくことがある（30 MiB から警告を出し、上限を超えるとバックエンドが保存を拒むため、その保存は捨てられる）。
- コミックの元に戻すはレイヤーを戻さない。アシスタントがレイヤーを変えると、ページのストア自身の元に戻すは消える。
- ページのインペイントは、ほかの生成と同じくモデルとエンジンが必要。ページは今描かれているままの状態で、ボックスの下の自身の解像度で描画する。
