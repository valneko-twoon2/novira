# コミックの 3D ラフ

コマの構図を 3D で組む。人物はマネキン、小物と床は遠近のあるカメラ越しに見る。適用すると、コマの OpenPose 画像と深度マップを焼き込み、2 つの ControlNet レイヤーがそれを読むので、人物と舞台がラフの位置に立つ。

## 動作

### ラフが持つもの

- コマは、`poses` と `poseImageName` に加えて、`rough`（`frontend/src/state/comic/rough.ts` の `ComicRough`）と `depthImageName` を持てる（[01-comic-canvas.md](../01-canvas/01-comic-canvas.md)）。単位はメートルで、y が上、床は y = 0。
- カメラは目標点を中心に回る。ヨー、ピッチ（`ROUGH_PITCH_MAX` で抑える）、距離、垂直の画角（`ROUGH_FOV`）を持つ。人物は、自身の空間（足裏から上が y、+z を向き、右側が -x）での OpenPose の 18 関節と、立つ位置（x、y、z）とヨー。小物は、箱、直立した板、直立した円柱のいずれかで、底面の中心、ヨー、大きさ（`ROUGH_SIZE`）を持つ。床はオフにできる。
- 人物は最大 `ROUGH_PEOPLE_MAX` 人、小物は最大 `ROUGH_PROPS_MAX` 個。`parseRough` は保存したラフを外部のデータとして読む（境界を参照）。新しいラフは、立っている人物 1 人、床、既定のカメラを持つ。

### エディター

- コマのポーズツール（`frontend/src/features/comic/PanelTools.tsx`）の「3D ラフ」で開く。ツールは、コマがラフを使っているか、深度マップが破棄されたかを表示する。
- 深度マップが最新のあいだは、コマ自身のラフで開く。そうでないときは（`roughPanel.ts` の `roughFor`）、ラフのカメラと小物か新しいラフを取り、コマの現在の人物をカメラの前に立たせる（`roughView.ts` の `liftPoses`）。各人物はカメラを向いた平らな図形（右肩が絵の右にあるときは背を向ける）で、カメラの視線に垂直なので、上下を向くカメラでは傾き、大人の胴の高さが図形の高さと同じになる距離に置く。これでカメラはポーズを元のとおりに見る。この人物は床より下に立つことがある。床まで上げるのは、持ち上げ操作を与えたときだけで、回転では動かない。ラフもポーズもないコマは、立っている人物 1 人で始まる。
- ビュー（`features/comic/rough/scene.ts`。three.js はエディターを開くときに読み込む）は、コマの形とラフのカメラそのもの。人物や小物のドラッグは同じ高さで動かす。選んだ人物の色付きの関節のドラッグは、その関節がぶら下がる関節を軸に手足を振る（`state/pose/math3d.ts` の `aimBone`、`swingJoint`。首は人物を動かす）。背景のドラッグはカメラを回し、Shift か右ボタンは平行移動、ホイールは近づける。ビューは焼き込みと同じ三角形で描き、テーマに従う。
- サイドパネル（`RoughDialog.tsx`、編集は `roughEdit.ts`）は、人物、箱、板、円柱を追加し（新しい板は目標点の後ろに、ほかは横に立つ）、舞台にあるものを一覧し、選んだものの回転、床からの高さ、大きさを設定する（人物の大きさは大人に対する割合で、胴の長さで保ち、`PERSON_SIZE` の範囲内。変更は表示した整数のパーセントではなく正確な大きさからの拡縮）。削除、画角、床、カメラの戻しもここにある。小さい画像が、ControlNet が受け取るものを示し、変更の少し後に焼き込む。
- WebGL がなければ、ビューがそう表示する。サイドパネルと「使う」は動く。

### 焼き込み

- 「使う」（`applyRough`）は、コマの絵の大きさで焼き込む。舞台の三角形（`roughMesh.ts`：箱の胴、球の頭、首と手足の円柱、手の球、足の箱。各人物のパーツは胴の長さに比例した太さ。小物。地平線までの床）を、カメラ越しに深度バッファへ描く（`roughBake.ts`）。各三角形はカメラの前の `NEAR` で切り、距離の逆数で塗り、最も近いものを残す。
- 深度マップは距離の逆数で、最も遠い面（黒）から最も近い面（白）まで引き伸ばす。何もない所は黒。
- 関節は、マージンを超えて手前に面があるとき隠れる（大人で 0.15 m、人物の大きさに応じて増える）。後ろ姿の顔、横向きの奥の腕、机の後ろの脚などが該当する。カメラの後ろにある関節は隠れ、カメラから見える最も近い関節の位置を取る（カメラの完全な後ろにいる人物は絵の外に立つ）ので、コマの人物ボックスは人物の上に残る。絵の外にある関節は残す。OpenPose 画像は、隠れた関節を除いて、`drawPose` と同じに関節を描く。
- 2 つの画像はギャラリーの制御画像としてアップロードする。コマは次に、ラフ、コマに対する割合の人物（その `poses`。吹き出しと領域が働き続ける）、`poseImageName`、`depthImageName` を 1 回の元に戻す手順で取り込む（`setPanelRough`）。ただし、画像を保存している間にコマのポーズが変わったときは、そのポーズが残り、通知で知らせる。描画は焼き込み中のものを待つ（`trackPose`、`posesReady`）。

### 描画とそのほかのポーズ変更

- 深度マップのあるコマは、ポーズの後に、`controlType` depth の制御レイヤーとして送る。ControlNet は深度用の名前のもの、なければ統合型（`state/poseSkeleton.ts` の `pickDepthModel`）で、強さは `DEPTH_CONTROL`。そのようなモデルがなければレイヤーを外してコマが警告する（`comicWarnings`）。深度マップの縦横比がコマと 2% を超えてずれている場合も同じ（焼き込み後に切り方やページの大きさが変わった。`request.ts` の `roughOutOfShape`）。警告はラフを使い直すよう伝える。
- ほかの方法で入れたポーズ（`setPanelPose`：ポーズエディター、既製のポーズ、アシスタントの `pose` 操作、コマのテンプレート）は `depthImageName` を外し、ラフは残す。
- アシスタントは、深度マップが最新のコマで `rough: true` を見る。その指示は、頼まれない限りそのポーズに触れないよう伝える。ラフは編集できない。

## 境界

| 境界 | 防ぎ方 |
|---|---|
| コミック文書に保存したラフ（データベースかファイルから読み戻す） | `parseRough` はオブジェクトだけを取る。すべての数は有限で、範囲内に収め（置き場所は `ROUGH_EXTENT` 以内、関節は人物から 4 m 以内、大きさ、画角、距離、ピッチ）、丸める。人物には関節の数がちょうど 54 個必要。未知の形は捨てる。ID は 80 文字以下の文字列で、同じ ID は最初のものを残す。個数は上限で切る。焼き込みの仕事量は、これらの個数とコマの絵の大きさで上限がある。 |
| 焼き込んだ画像 | ページ内のキャンバスに描き、ポーズエディターの画像と同じく `uploadImage` でアップロードする。コマはそのギャラリー名だけを保存する。 |
| three.js | エディターを開くとき、動的 `import()` でアプリ自身のファイルから読み込む。ネットワーク、eval、CSP の変更はなし。 |

## 既知の限界

- マネキンは粗い。強い深度レイヤーは、その形をそのままなぞる。`DEPTH_CONTROL` は WAI-illustrious-SDXL と xinsir の統合 ControlNet だけで調整した。
- 真横や真上から見た人物は、マージンのところで関節が隠れたり見えたりすることがある。マージンは体全体で 1 つの数。
- 持ち上げた人物はカメラを向いた平らな図形で、その奥行きと向きはユーザーが与える。
- コマの `poses` は隠れた関節を持たない。何かに隠れた関節は人物の上の位置を保ち（ボックスと頭は正しいまま）、ポーズエディターはそれを見えている関節として表示する。後ろから見た既製のポーズと同じ。
- ラフのビューとドラッグは、ソフトウェア WebGL のヘッドレス Chromium だけで確かめ、アプリの Web ビューでは確かめていない。
