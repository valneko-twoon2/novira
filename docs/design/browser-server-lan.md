# Browser server on the home network

The browser server ([browser-server.md](browser-server.md)) can also open a second listener for the devices of the home network, so a phone on the same Wi-Fi can use novira in its browser. That listener speaks TLS only, with a certificate from a CA made on this computer, opens only on a network this computer's owner trusted, closes when unused, and lets a device in only after this computer approved its pairing ([browser-server-pairing.md](browser-server-pairing.md)). Until this computer's page opens it, nothing here is listening and the server stays on this computer.

## Behaviour

- `novira-server` (every start, with no option) keeps the loopback listener as it is (plain HTTP on `127.0.0.1`) and makes the home-network listener available (`Server::enable_lan` with a `Control` in `backend/crates/novira-server/src/lan.rs`). It never opens it at the start: the QR item of this computer's page does (below). The listener (`Server::open_lan` in `backend/crates/novira-server/src/lib.rs`) binds this computer's home address only, on a port of its own (the last one, kept in `server-lan-port` in the data folder, else a free one). It opens and closes as a unit: closing frees the port, ends its connections and event sockets, and ends every session and pairing code.
- The home address is the one the routing table picks for an address off the local network: a UDP socket is connected to `192.0.2.1` (a documentation block), which sends nothing (`home_address` in `backend/crates/novira-server/src/home_network.rs`). When that address is not one a home router hands out, it says only this computer can open the page.
- TLS (`backend/crates/novira-server/src/tls.rs`): rustls with the ring provider, TLS 1.2 and 1.3, HTTP/1.1 only. The "novira local CA" (ECDSA P-256, ten years, path length 0, keyCertSign and cRLSign) is made once per data folder; its key and certificate are a DPAPI secret (`Secret::LanCa`, `novira-data/secrets/lan-ca.key`), and its certificate is written to `lan/ca.pem` in the data folder. Its name constraints permit only the IP subnets `10/8`, `172.16/12`, `192.168/16` and `100.64/10` and exclude every DNS name. At every opening a new leaf (90 days, serverAuth, the home address as its only name, no common name) is signed for the current address, so a new address needs no new CA. An unreadable secret makes a new CA, which a phone installs again.
- **Trusted networks** (`backend/crates/novira-server/src/trusted.rs`). A network is told by the hardware address (MAC) of the gateway of the interface that has the home address: its default route's next hop (`GetIpForwardTable`), found in the neighbour table or asked with ARP (`gateway_mac` in `home_network.rs`). The networks this computer's owner confirmed are `[{gatewayMac, label, addedAt}]` in `<data>/lan-trusted.json` (written whole through a temporary name; a file that cannot be read trusts nothing and an entry that is not well formed is dropped; at most 32). The listener never opens on an address whose gateway cannot be told (not Windows, no default route, no answer), nor on a gateway not in the list. Windows calling the network public is only a flag in the state.
- **On demand** (`/lan/*`, this computer's page only; they answer 404 `no_lan_control` when no `Control` was set, which `novira-server` always does unless the CA could not be made). `GET /lan/state` answers `{open, address, port, network: {gatewayMac, trusted, label}, windowsPublic, idleSecs, idleLimitSecs, codes, devices, pending, trustedNetworks}` (`address` is the open listener's, else the one it would open on; no secret). `POST /lan/trust` with `{gatewayMac, label}` trusts the network this computer is on now, which the owner saw as `gatewayMac` (409 `network_changed` if it is another one by now; 409 `unknown_network`, `no_home_network`). `POST /lan/untrust` with `{gatewayMac}` removes one and closes the listener at once if it is open on it. `POST /lan/open` opens it on a trusted network (409 `untrusted_network` with the gateway to confirm, `unknown_network`, `no_home_network`; an open listener stays as it is). `POST /lan/close` closes it.
- **Closing by itself** (`maintain` in `lan.rs`, every 30 seconds): after 30 minutes with no request from a paired device (an open event socket of one counts) and with no pairing code that can still be used and no request waiting for approval; and at once when the home address is gone or changed, or the gateway is known and no longer trusted. A gateway that cannot be told for a moment does not close it. Requests from anyone who is not paired do not count as use.
- `GET /ca.crt` (`CA_ROUTE`) answers the CA's certificate (PEM, `application/x-x509-ca-cert`) to anyone the listener answers, with no token: a phone fetches it before it trusts the listener.
- The console prints only the usual `novira-server: http://127.0.0.1:<port>/?token=<token>` line. The side bar's QR item on this computer opens the listener, trusts the network it is on (pressing the item is the owner's choice) and shows a fresh pairing code and the CA's SHA-256 fingerprint to compare with what the phone shows (browser-server-pairing.md).
- Once paired, the phone's page is the same app with the same saved screen state (settings-engine.md), in the layout made for a phone ([phone-layout.md](phone-layout.md)). The frontend picks `wss:` for `/events` on an `https:` page.

## Boundaries

| Boundary | Guard |
|---|---|
| Who is answered | The loopback listener answers loopback only; the plain HTTP listener never answers another device. The home-network listener answers a peer only when the address it came in on is one a home router hands out (private `10/8`, `172.16/12`, `192.168/16`, or shared `100.64/10`) and the peer is on the subnet of that address. The mask comes from the system's address table (`GetIpAddrTable`) once per connection; a mask that is not a run of ones, wider than `/8` or a single address answers nobody; outside Windows no mask is read, so no other device is answered. Anything else is 403 before any credential is looked at. |
| Transport | TLS only on the home-network listener: a connection must finish its handshake within the header timeout, so plain HTTP there, or a silent socket, is dropped without an answer. It has its own `MAX_CONNECTIONS`, so a flood from the network cannot take this computer's own page. |
| Certificates | The CA's name constraints keep a copy of its key from vouching for any DNS name or public address, for clients that enforce them (tests in `tls.rs` check with rustls-webpki that a leaf for a home address verifies and one for `example.com`, a single label, a wildcard or `8.8.8.8` does not). Its key never leaves the DPAPI secret; `/ca.crt` and `lan/ca.pem` hold only the public certificate. |
| `Host`, `Origin` | `Host` is exactly the address the connection came in on with the port (`127.0.0.1:<port>`/`localhost:<port>` only on loopback). A DNS name pointed at this computer, another port or a bare address is 403. `Origin`, when sent, must be `https://<that Host>` on the TLS listener and `http://` on loopback. |
| Page content | `connect-src` names `wss://<the checked Host>` on the TLS listener (`ws://` on loopback) beside `'self'`. |
| Credentials | A device (non-loopback peer) gets in only with a session this computer approved, from the address it paired from; the start token is no credential there and never leaves this computer (browser-server-pairing.md). The only routes without one are `/ca.crt` and the pairing page and its calls. Cookies set on the TLS listener are `Secure`. |
| What a device may run | A home-network device (any non-loopback peer) is refused the `LOOPBACK_ONLY` commands (`backend/crates/novira-server/src/lib.rs`): installing or running software (model, pack and ComfyUI version changes, the engine restart), engine and model-folder settings, the API keys, and the assistant's setup (sign-in, the server address). It gets generation, the queue, the gallery, boards, workflows, the screen state, reads, and a chat with the assistant set up on this computer (`agent_chat` and its tool answers, cancel, the fact look-up): its `claude`/`codex` runs with its own tools off and acts only through the app's tools, none of which installs or deletes (assistant.md). The refusal is 403 `not_available_over_network`. This computer's own loopback page keeps full access. |
| Which network | The listener opens only when the gateway of the home address's interface is a trusted one (`trusted.rs`, `lan.rs`): never on an unknown gateway or off Windows, and it closes if the network changes or stops being trusted. `/lan/trust` names the gateway the owner was shown and is refused if the network moved on; `/lan/*` are loopback with the token only (403 for any device, session or not). |

Tests: `backend/crates/novira-server/src/home_network.rs` (ranges, subnets, masks, the system table on loopback, the gateway), `backend/crates/novira-server/src/trusted.rs` (the file, a bad file, the cap), `backend/crates/novira-server/src/lan/tests.rs` (untrusted, unknown and absent networks, trusting with hostile bodies, the routes refused to devices, closing, the idle close, a changed network), `backend/crates/novira-server/src/tls.rs` (the name constraints, the CA kept per data folder), `backend/crates/novira-server/src/lan_tests.rs` (a device's requests through the router in process: the subnet, the plain listener), `backend/crates/novira-server/tests/lan_tls.rs` (a rustls client on loopback that checks the certificate for the home address: the handshake, other names and CAs, plain HTTP on the TLS port, `/ca.crt`, the origin and cookie, opening and closing) and `backend/crates/novira-server/tests/home_network_live.rs` (the real home address; it listens on the network, which makes Windows ask about the firewall for each new test build, so it runs with `cargo test -p novira-server --test home_network_live -- --ignored`).

## Known limits

- Until the phone has installed the CA it sees a certificate warning; whoever answers in its place then (on a shared Wi-Fi) is not detected. Nothing compares the CA's fingerprint on the two screens any more, so a phone that installs a certificate on an untrusted Wi-Fi cannot tell it is the right one. Firefox on Android ignores user CAs by default.
- Name constraints bind only clients that enforce them; a stolen CA key could still sign for a home address. The key is as safe as the other DPAPI secrets (security.md).
- Every device on the same subnet reaches the listener at the network level (the CA, the pairing page and its calls); a session is what keeps them out of the app. A guest network on the same subnet is the home network to the server.
- The gateway's hardware address is not secret and can be copied by a rogue access point; it tells the owner's networks apart from other ones, it does not prove the gateway. It is read once a half minute, so a move to another network closes the listener within that time.
- Windows asks once per program whether `novira-server.exe` may accept connections; allowing it on public networks is needed when Windows calls the home network public (Settings can set it to private instead).
- Sessions end with the server, so the phone pairs again after each start.
- Only IPv4. A phone reaching this computer through a VPN (Tailscale and the like) comes from another subnet and is refused. A new home address needs a restart of the listener (a new leaf).
