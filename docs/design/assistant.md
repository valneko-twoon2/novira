# AI assistant

A chat that sets up the app and answers questions about it. The model acts only through tools (settings, editors, queue, extension suggestions, app guide). It runs on the user's own `claude` or `codex` command-line tool (signed in with its own login), or on a server with an OpenAI-compatible API such as Ollama. All three get the same tools, prompt and checks.

## Behaviour

- Window (`frontend/src/features/agent/agent.css`): floats over the app's panels (`--z-assistant`, 500), under the dialogs (`--z-modal-overlay`, 800), menus, popovers and tooltips, so it never covers them; its model picker stacks just above it (`--z-assistant-popover`, 501). The layers are tokens in `frontend/src/theme/tokens.css`; `frontend/tests/assistant-layer.test.ts` reads them.
- On a phone the chat is a screen of its own ([phone-layout.md](phone-layout.md)); sign-in and the server's settings stay on the PC.
- Provider: `AgentProvider` is `claude`, `codex` or `openai` (`backend/crates/novira-core/src/agent/mod.rs`). The choice is saved in `<data>/agent.json`, never the key. `agent_login` saves the choice and runs `claude auth login` or `codex login` (the browser opens; up to 300 s). Status comes from `claude auth status` or `codex login status` (`backend/crates/novira-core/src/agent/cli.rs`).
- Models: Claude runs `fable`, `opus`, `sonnet` or `haiku` (`--model`), or a typed name in `ANTHROPIC_MODEL` when it has letters, digits and `.-_[]` (at most 64). Efforts are low to max (default high). Codex runs only models listed in its `models_cache.json` with the efforts each lists. An effort the model does not take is dropped. The choice per tool is kept in the window (`novira.agent`) (`backend/crates/novira-core/src/agent/models.rs`).
- CLI request: one headless run per message. Claude: `-p --tools "" --setting-sources "" --strict-mcp-config --allowedTools mcp__novira`, the app's server given by `--mcp-config`. Codex: `exec --sandbox read-only --ignore-user-config --ignore-rules`, the server by `-c`, the answer read from `-o`. The prompt goes on stdin (`backend/crates/novira-core/src/agent/chat.rs`).
- Server request: the Rust backend calls `POST {base}/chat/completions` (with `stream: false`) and `GET {base}/models` itself. `backend/crates/novira-core/src/agent/toolloop.rs` sends the rules and tools as function definitions, runs each returned call through `mcp::dispatch`, and stops when the model answers without a call.
- Test connection (`agent_endpoint_test`) checks the model list and one tool round trip with `get_screen`, whose answer is canned and not run. A model that cannot call tools, or a server that cuts the request short (`toolloop::cut_short`), is recorded with its reason and refused until a new test passes or the server or model changes.
- Pictures sent to the model (attachments; a drawn comic page): [assistant-pictures.md](assistant-pictures.md).
- Prompt (`backend/crates/novira-core/src/agent/prompt.rs`): English rules (`INSTRUCTIONS`), the locale, the screen (`currentScreen()`), the extension asked about, and the last 10 turns. Models, settings and graphs are not in it; the model reads them with tools. The final answer is plain text in the user's language, optionally starting with a `<thoughts>` block of up to 8 lines of 300 characters; the text is cut at 20000 characters (`backend/crates/novira-core/src/agent/reply.rs`).
- Tools (`backend/crates/novira-core/src/agent/tools.rs`, `TOOLS`): 28, each with a description and a JSON schema. Read-only (18): `get_screen`, `get_app_guide`, `get_manga_guide`, `list_models`, `get_generation_settings`, `get_queue_status`, `get_comic_page`, `view_comic_page`, `get_text_scene`, `get_workflow`, `search_comfy_nodes`, `get_form`, `get_pose`, `list_gallery_images`, `get_image_info`, `search_extensions`, `lookup_reference`, `recommend_packs`. Changing (10): `select_model`, `add_lora`, `set_generation_settings`, `generate`, `edit_comic`, `edit_text`, `edit_workflow`, `create_workflow`, `set_form`, `set_pose`.
- `lookup_reference`: [assistant-web-lookup.md](assistant-web-lookup.md).
- Argument checks (`tools::check_call`): type, enum, length, count, range and required fields; unknown fields are refused only where the schema sets `additionalProperties: false`. Arguments are at most 512 KiB; an edit carries at most 400 operations (`MAX_OPS`).
- `mcp::dispatch` (`backend/crates/novira-core/src/agent/mcp.rs`) is the one path: it counts the call against the request's cap (150, `MAX_TOOL_CALLS`), runs the checks, then hands it to the handler. For the CLIs the app's MCP server (Streamable HTTP, JSON answers, `initialize`, `ping`, `tools/list`, `tools/call`, on `127.0.0.1`) carries the calls for one request.
- Relay (`backend/crates/novira-core/src/agent/relay.rs`): each call goes to the window as an `agent_tool_call` event (`callId`, `tool`, `args`, `readGated`); the window answers with `agent_tool_result`. A call waits 120 s, or 600 s when read-gated; no answer is an error for the model.
- Window (`frontend/src/state/agentTools.ts`): each handler uses the feature's own applier: the editors registered with `registerAgentEditor` and the Generate tab's parameters. Text operations drop unknown fonts, bad colours and out-of-range numbers (`frontend/src/features/text/aiOps.ts`); a workflow edit that does not parse as a workflow changes nothing (`frontend/src/features/workflows/aiOps.ts`). Answers over 200000 characters are refused.
- Workflows with ComfyUI's nodes: `get_workflow` lists the editor's own nodes and the ComfyUI nodes the recipes use; `search_comfy_nodes` (`frontend/src/features/workflows/agentNodes.ts`) finds the rest of the nodes ComfyUI reports (and of installed extensions) by a few words, at most 20 a call, each with its `comfy:<Class>` type, inputs (choices, defaults, the inputs of a choice, links, gallery files) and outputs, or lists the groups when it has no words; while ComfyUI is not running it answers `ready: false`. An edit answers with `skipped` (each operation or part left out and why: an unknown type, a connection between types that do not fit, a value for an input the node does not take); a graph with an unknown node type is not opened and the answer says which; the graph the tools return carries `problems`, the reasons the Invoke button is blocked (`readinessReasons`). The assistant builds graphs but does not run them: no tool queues a graph.
- An editor may give `edit_*` a short `answer` instead of its whole context (the comic does, `comicAnswer`).
- Undo: before the first change of each kind, the request keeps the Generate settings and each editor's data; one undo per answer restores them (`undo` in `frontend/src/state/agent.ts`). Queued jobs and saved pictures are not undone.
- One request runs at a time (`backend/crates/novira-core/src/service/assistant.rs`), within 15 min (`CHAT_TIMEOUT`); `agent_cancel` ends it, and its changes so far can still be undone.

## Boundaries

| Boundary | Guard |
|---|---|
| AI assistant | Runs the user's own `claude` / `codex` with its built-in tools off (Claude: `--tools ""`, `--setting-sources ""`, `--strict-mcp-config`, only `mcp__novira` allowed; Codex: read-only sandbox, `--ignore-user-config`, `--ignore-rules`), prompt on stdin, fixed arguments. The one argument that is not fixed is a Codex model (`-m`): only a model listed in Codex's `models_cache.json` (read up to 4 MB, hidden models left out) whose name is letters, digits and `.-_` (at most 64, not starting with `-`); a typed Claude name goes in `ANTHROPIC_MODEL` instead. The model acts only through the app's tools: no tool deletes pictures or installs models, packs or programs, and `generate` only queues what the user asked for. Every call's arguments are checked against the tool's schema at the server, and the window checks each operation again. The final answer is plain text (at most 20000 characters); its thoughts lines are cut to 8 of 300 characters and shown as text. `agent_cancel` takes no argument and only stops the request that is running (its process is killed and its waiting calls end). |
| Assistant on an OpenAI-compatible server | It is a server the user names. Every call is made by the Rust backend (`backend/crates/novira-core/src/agent/endpoint.rs`); the window never contacts it, `connect-src` stays closed, and `agent_endpoint_save`, `agent_endpoint_models` and `agent_endpoint_test` check their arguments at the entry. The address must be `http` or `https` with a host, and no user name, password, query, fragment or space. A server away from this PC over plain `http` is flagged as unencrypted, and any address away from this PC as one that receives what the assistant reads. The key is a DPAPI secret (`<data>/secrets/assistant-endpoint.key`), sent only in the `Authorization` header to the saved address (a typed key goes to the address typed in the form), never returned to the window, never in a log, and cut out of every error text. Saving another address without a new key drops the saved key. Redirects are followed only inside the same host (and from `http` to `https`), at most three; a server on this PC is not reached through a proxy. Limits: 10 s to connect, 5 min per call, 15 min per request; answers capped at 4 MiB (model list 1 MiB, error text 64 KiB; a server's message is shown cut to 300 characters). The server's replies are data, and its tool calls go through the same `mcp::dispatch` as the MCP server's, so this provider has no weaker path. A model that cannot call tools is refused, not worked around. |
| Assistant tool server (loopback) | Listens on `127.0.0.1` with an OS-assigned port only while one assistant request runs, and only one request runs at a time. Each request has a fresh random bearer token (two v4 UUIDs): Claude gets it in a config file in the request's own temporary folder (deleted afterwards), Codex in the environment variable `NOVIRA_MCP_TOKEN`, never as an argument. Refused before anything runs: a wrong or missing token (compared in constant time), a `Host` other than `127.0.0.1:<port>` or `localhost:<port>` (DNS rebinding), any `Origin` header (a web page), another path, a head over 16 KiB, a body over 1 MiB, chunked or length-less bodies, a content type other than JSON, non-JSON bodies, batches. At most 150 tool calls and 15 minutes per request. A call goes to the window as `agent_tool_call`; the answer comes back through `agent_tool_result`, which takes only an id of the form the relay makes for a call still waiting, and an answer over 256 KiB becomes an error. A call nobody answers ends as an error, never as data. |
| Assistant reads of pictures and prompts | `list_gallery_images`, `get_image_info`, `view_comic_page` and `get_generation_settings` with `includePrompts` are tagged read-gated by the backend (`is_read_gated`, `backend/crates/novira-core/src/agent/tools.rs`) and by the window (`isReadGated`, `frontend/src/state/agentTools.ts`). The backend only tags the call; the window applies the user's setting `assistantReadAccess` (`always`, `ask` each time (default), `never`). "Ask" shows a question in the chat window; a decline, a stop or "never" answers the model with an error saying the user declined. Pictures the user attaches are sent without the question; the one tool that returns pixels is in [assistant-pictures.md](assistant-pictures.md). Attached names are checked like gallery names, and a missing one stops the request before the provider starts. Gallery answers carry picture names, sizes, dates, models and prompts (cut to 300 characters in lists), never file paths, and leave helper pictures out. |

## Known limits

- With an OpenAI-compatible server the user's requests, and (when the read setting allows it) prompts and picture details, go to the address the user entered. Away from this PC, over plain `http` they are readable on the network; over `https` the server's operator can read them. The window warns of both, but the user decides. The app does not stop addresses on a private network, so an address entered by mistake, or one a hostile instruction puts in front of the user, can make the app send requests there. A hosted server's reply can still mislead the model.
- While a request runs, another program of the same Windows user can find the tool server's port and could read the Claude config file holding the token; such a program can already act as the user. The token stops web pages and other users' programs. The editors the assistant works on (comic, text, workflow, forms, poses) are read without asking; only gallery pictures and the prompt boxes of the Generate tab are behind the permission setting.
- Descriptions from the ComfyUI Registry and of installed extensions reach the model through `search_extensions`. They are written by third parties; the instructions say to treat them as data, but a hostile text can still mislead a model. The damage is bounded: no tool installs or deletes anything, `recommend_packs` only shows cards the user installs by pressing the button, and settings and editor changes of a request can be undone at once (queued jobs cannot).

## Not implemented

- Streamed answers: each request waits for its final answer (server requests use `stream: false`).
